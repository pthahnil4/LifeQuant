# 幽灵账本冻结全账户开仓 — 事故诊断与处置

> 结论先行：定时任务本身没算错，策略每轮都算出了正确的区间挂单目标价；真正的问题是
> **一条误拼留下的"幽灵账本" `NAER-USDT-SWAP` 触发了账户级对账闸门，把整个账户本轮的
> 开仓额度清零，于是所有币种只能"无动作"**。修复代码此前已写好但**未提交、线上进程也未
> 加载**（典型的"改完代码不等于线上生效"）。本次把处置口径与工具隐患一并坐实。

## 一、现象（2026-09-27 22:0x 一轮）

- 趋势仓：`【仓位停用】趋势仓 | 撤销挂单0笔` —— **这是配置**：`trend_position.enabled=false`，属正常，非故障。
- 区间仓：打出 `【区间独立挂单】方向=long 目标开仓价=… 目标平仓价=…`（keltner 触发价都算对了），
  紧接着心跳却是 `… | 无动作`，且**交易所里从头到尾没有任何区间开仓挂单产生**。
- 同一轮更早（22:03:35）日志：`账户存在未完成对账的合约，暂停本轮增仓: ['NAER-USDT-SWAP']`。

## 二、根因链（逐环证据）

| 环节 | 事实 | 证据 |
|---|---|---|
| 1 脏数据来源 | `quantlimit` 账号(实盘 flag=0)账本里有一条 `pos_v2:c99d53a1029164b7ab27:NAER-USDT-SWAP`，同账号另有正确的 NEAR | 只读查 MySQL kv_store |
| 2 记录内容 | 该行 trend/range 全 `held=0`、槽位 `IDLE`、`lev_set=null`，唯一实质字段是残留 `"sync_error":"持仓、订单或账户模式查询不完整"` | 读取该 kv 值 |
| 3 合约不存在 | OKX 实盘返回 **51001**：NAER-USDT-SWAP 无此合约 | 体检脚本联网 `instrument_exists` |
| 4 纳入对账范围 | 轮初 `instruments = 配置 ∪ pos_mgr.state ∪ 交易所持仓/挂单`，NAER 来自 `pos_mgr.state` | `trend_range_trader.run_real_trading_batch` |
| 5 对账失败 | `_read_positions_by_mode('NAER…')` 永远返回 None → 进 `failed_sync` | 同上 |
| 6 账户级闸门落下 | `_account_sync_ok = not failed_sync` → **False**（一个幽灵拖累全账户） | 第 3509/3514 行 |
| 7 开仓额度清零 | `_entry_room()` 首句 `not _account_sync_ok → return 0.0` → 每个币 amount=min(目标,0)=0 → 静默跳过挂单 | `position_order_manager._entry_room` 697 行 |

净效应：策略算得出价、写单动作却被账户级闸门整体掐断，且因去重/静默早退，日志里看不到直接报错——只剩满屏"无动作"。

## 三、修复状态

### 已存在但未上线（前一轮会话产物，本次核实）
- `crypto/task/trend_range_trader.py` 的 `_partition_sync_scope()`：把"既不在配置、交易所也无持仓/挂单足迹"的账本条目**摘出对账范围并从内存账本丢弃**；仅带风险标记且合约确证不存在（幽灵）→ 跳过；有真实敞口/在途单 → 绝不跳过（保守报错等人工）。彻底解决"一个幽灵冻结全账户"。
- 配套离线回归 `crypto/task/_smoke_sync_scope.py`：**21/21 OK**，覆盖幽灵带 sync_error、闲置空条目、目录外合约、存在性未知(网络失败≠不存在)等全部口径。
- 二者均为 **未提交** 状态，线上常驻进程仍跑无此逻辑的旧版本 → 现象依旧。

### 本次新增修复（工具隐患）
- `crypto/task/_cleanup_ghost_ledger.py` 的 `configured_insts()` 原先只读**全局** `strategy_config`；而调度器读的是**账号作用域** `strategy_config:quantlimit`。口径不一致会把 quantlimit 正在交易的 ETH/LTC/SOL/XRP 误判成"不在配置→可删闲置账本"，若有人跑 `--include-idle` 会**误删在交易币种的账本**。已改为 `load_strategy_config_cached(account)`，与调度器一致。
- 复跑只读体检（改后）：quantlimit 配置识别为 ETH/LTC/SOL/XRP，四者归入"受保护/在配置中"；**唯一 GHOST = NAER-USDT-SWAP**。

### 本次新增修复（静默无动作的可诊断性）
- 症状复核：四币 `trade_enabled=True`（非观察模式，`trade_executor._write` 闸门不触发）、区间 `enabled=True`、`size_mode=usd notional_usd=1×杠杆10` 按真实合约规格折算 ETH/SOL/LTC/XRP 得 0.03/0.08/0.1/0.06 张，**均 ≥ minSz**，排除"配置级折算=0 拒单"。唯一命中：`position_order_manager._entry_room` 因幽灵 NAER → `_account_sync_ok=False` → 每币额度=0 → `_place_entry` 在 `amount=min(目标,0)=0` 处**静默 return False**，心跳只留"无动作"看不出原因。
- 修复（`crypto/task/utils/position_order_manager.py`，返回值与额度计算不变，纯增诊断）：`_entry_room` 每个额度归零出口写入 `_last_room_reason`（账户对账未过/对账屏障/人工冷却/未设目标/他币风险拖累/额度已满），新增 `_note_entry_blocked()` 按"币种+原因"去重打一行 `【开仓跳过】区间波动/趋势跟踪 开X未挂单：<原因>`；`_place_entry` 两处静默 return 调用它。下次再遇"无动作"，日志直接点名是幽灵账本还是别的闸门。
- 验证：AST + ruff(F821/F822/F823/E9) 通过；离线回归 `_smoke_manual_override_regression` 43/43、`_smoke_fix_regression` 37/37、`_smoke_sync_scope` 21/21 全绿。

## 三点五、复发防护（本次新增：保存配置时硬校验合约存在）
- 根因是"手误拼错合约名"。旧校验只查格式 `^[A-Z]+-USDT-SWAP$`，NAER 完全合规→直达保存。
- 已在 `crypto/app.py` 保存路由 `save_trading_config` 新增 `_validate_instruments_exist(currencies, account)`：按账号 `flag` 取 OKX 规格缓存，逐个 `instrument_exists`，**确证不存在（False）直接拦报错**；查询失败（None，网络/限频）保守放行不误伤正常保存。校验在 `errors` 返回处早于 `_save_trading_config` 与 `_upsert_coin_library`，因此幽灵名不会再进入交易配置与币种历史库。
- 实测：`NAER-USDT-SWAP→False`（会被拦）、正确的 `NEAR-USDT-SWAP→True`、`ETH→True`。
- 残留范围复查：kv_store 中除幽灵账本键 `pos_v2:…:NAER-USDT-SWAP`（按键名含 NAER）外，`task_coin_history_library` 的 value 也因旧保存含过 NAER（不影响交易，可后经币种库删除路由清理）。

## 四、处置 Runbook（按序，须在生产侧执行）

> 前置：本仓库代码 = 权威修复版；线上生效需"部署 + 重载"。清库脚本对**生产库**且要求**调度器已停**，属破坏性操作，务必人工确认后再执行。
>
> **重要结论**：只要部署带 `_partition_sync_scope` 的版本并重载，幽灵 NAER 会被逐轮从内存对账范围摘出（不进 `to_sync`→不计入 `failed_sync`→`_account_sync_ok` 保持 True），**交易即刻恢复，无需任何写库/清库操作**。下方清库仅为可选的彻底扫尾，不做也不影响交易。

1. **提交并部署** `trend_range_trader.py` + `_smoke_sync_scope.py`（本次一并提交 `_cleanup_ghost_ledger.py` 口径修复），重启/reload 实盘调度进程。
   - 仅这一步即可**立即解冻**：新版每轮把 NAER 幽灵条目摘出同步并从内存丢弃，`_account_sync_ok` 恢复 True，各币恢复挂单。
2. **（可选，彻底清脏库键，防止重启后再回来）** 先停实盘调度器，再跑体检确认，最后 apply：
   ```
   # 只读体检（不改库）
   python crypto/task/_cleanup_ghost_ledger.py --account quantlimit
   # 确认 GHOST 仅 NAER 后，停调度器再删
   python crypto/task/_cleanup_ghost_ledger.py --account quantlimit --apply --scheduler-stopped
   ```
   - **切勿在调度器运行时 `--apply`**：会与账本 `_revision` 乐观锁相撞，导致写入被永久 latch（fail-stop），反而彻底停开仓。
3. **验收**：重启后第一轮应出现 `轮初对账跳过 … 幽灵合约 … NAER-USDT-SWAP`（或体检已删则不再出现），ETH/SOL/LTC/XRP 心跳由"无动作"变为 `动作:range.entry挂单…张@价`；交易所可见对应限价挂单。
