# 交易卡通关标准纠正：8% 线回归「每日达标评级」

日期：2026-09-27
起因：第 3 轮交易卡（trade_8a460d28「第3轮 · 翻倍挑战」）于 2026-09-26 18:05 被手动结算为
failed——旧版 `_settle_card` 误把 `TRADE_GROWTH_THRESHOLD`（8%，本是**单日达标线**）
当成通关标准，该卡首末打卡余额 386.70 → 359.64（增长 -7%）即被判死、奖金归零。
用户裁定：**亏钱属正常，8% 线只是每日评级标准，不是任务完成标准；时间没到就还能赚回来。**

## 新规则口径（学习/交易卡统一）

| 维度 | 口径 |
|---|---|
| 通关标准 | 满 100 格打卡 **或** 任务树全部完成（两类卡一致） |
| 8% 增长线 | 仅进 `_calc_achievement` 每日达标率评级与前端展示，**不参与通关判定** |
| 资金增长快照 | 结算时仍写入 settlement（growth_pct 等）仅作记录；无余额数据时 growth_pct=None |
| 手动结算 settle-round | 未满 100 小时且任务树未全完成 → 400 拒绝（禁止提前手动判死），倒计时到期由 settle-expired 自动结算 |
| 倒计时到期 | 满 countdown_days（默认 10 天）自动结算：达标 completed，未满 failed 终止（与学习卡一致，余额未知不再阻塞） |
| 满 100 格自动结算 | fill-slot / backfill-batch 对两类卡都生效（旧版仅学习卡） |
| 提前通关资格 | `_calc_early_eligible` 两类卡统一看任务树是否全完成（旧版交易卡恒 True） |

## 代码改动

- `crypto/plan_routes.py`

  - `_apply_countdown_settlements`：移除上一版临时加的「余额未知暂缓结算」守卫
    （新规则下余额与通关无关），恢复为到期即结算。
  - `api_settle_round`：两类卡统一守卫，交易卡不再按 `_trade_growth known` 放行。
  - fill-slot / backfill-batch：满 100 格或倒计时到期自动结算扩展到交易卡。
  - `_calc_early_eligible`、常量注释、`_trade_growth` 文档字符串同步纠正。
- `crypto/static/js/task_plan.js`
  - 结算 Tab：交易卡不再无条件显示「结算本轮」按钮，与学习卡同口径（满 100h 或树全完成才出现）。
  - `settleCard` 前端兜底拦截 + 文案说明「倒计时到期会自动结算」。
  - 增长展示统一改为「每日达标线 >8%，不影响通关」；卡片正文提前奖行改为仅 early_eligible 时显示。
- 测试同步：`data/_countdown_probe.py`（26 项）、`crypto/_smoke_longtermism.py`
