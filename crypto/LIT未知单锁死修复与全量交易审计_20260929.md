# LIT 未知单锁死修复 + 全量交易审计（2026-09-29）

## 一、LIT-USDT-SWAP 连续失败：根因与修复（已定位、已修复、已测试）

**根因**：14:08 一笔区间 reduce-only 平仓单（2张@4.31207）遭遇 `SSL UNEXPECTED_EOF`，
请求根本没到交易所 → 下单结果为未知，账本里留下只带 `clOrdId`、无 `ordId` 的
`unknown=True` PENDING 孤儿单。此后每轮 `synchronize` 都会：

- `position_order_manager.py` `_poll_order` 按 clOrdId 反查，交易所**权威地**回答"查无此单"(`absent`)；
- 但旧代码把 `absent` 与"查询失败(`unknown`/`error`)"一视同仁 → 永久保留 `unknown=True`，无任何老化兜底；
- `synchronize` 见 PENDING+unknown → 抛"存在未知订单…禁止补单" → `_read_positions_by_mode` 返回 None
  → 该币"持仓/订单对账未通过，禁止交易"，每轮如此，触发"连续5轮执行失败"告警邮件。

该孤儿单至今已存续 **3.2 小时**仍不自解 —— 这就是 LIT 被永久锁死的机制。

**修复**（`crypto/task/utils/position_order_manager.py` `_poll_order`）：
新增 `UNKNOWN_ABSENT_SETTLE_SEC=300` 传播窗口。**仅限平仓(reduce-only exit)孤儿单**，
当交易所**权威查无此单(absent)** 且存续超过该窗口时，判定"从未落地"→主动过期释放槽位
（`state=EXPIRED, unknown=False`），下一轮按最新价正常重挂。开仓(entry)单**不适用**（保留
"absent 永不重发"的防重复开仓安全不变量）；查询本身失败(unknown/error)仍保守保留，绝不误清、绝不误重发。

- 对 reduce-only 平仓而言，重挂最多是被交易所按持仓上限拒掉，不可能重复开仓，安全。
- 300s 窗口覆盖 OKX 传播/归档延迟 + 数个调度轮，避免过早误判。

**测试**：`crypto/task/_smoke_manual_override_regression.py` 新增 3 例（exit 超窗过期 / exit 宽限内保留 /
entry 永不自动过期），全套 47 通过；全量冒烟 `_run_smokes.py` = FAILED:none。
