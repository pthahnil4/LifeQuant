## 一分钟大白话版（后面每一节都是这几句话的展开）

**一、现在坏在哪**

系统每轮开工前都要先盘一次账：本地记的仓位、挂的单，跟交易所实际的能不能对上。
对不上就拉闸，**整个账户都不许买**。
结果账本里残留了一行根本不存在的合约（NAER，NEAR 写错了），它永远对不上，
于是 XRP/SOL/LTC/ETH 四个正常币跟着一起被锁死，一锁就是很久。
**一个币的坏账，罚了全账户 —— 这就是病灶。**

**二、以后怎么拉闸：谁对不上就锁谁**

- 某个币自己盘不清 → **只锁这个币的买入**，它该卖的照卖、该撤的照撤，别的币完全不受影响；
- 只有**账户整体**都看不清有些什么（查仓位/查挂单直接失败）→ 才全账户先别买，但**卖和撤单照放行**；
- 只有连**账都写不进去**（存不了盘）时 → 才什么都不下单。因为存不了盘就等于下次开机不知道
  自己干过什么，重复下单没人能拦住。

**三、一句话记住原则：只拦“越买越多”，不拦“减少风险”**

买入是加大风险，卖上是减少风险。账目对不清的时候，最错的做法就是把“能保命的动作”（平仓、
撤单、止盈止损）也一起关掉。所以新规矩是：**闸门只能不让买，永远不能不让卖。**

**四、盘账前先分类：哪些要盘、哪些不用盘**

- **要盘的**：配置里写了的、交易所确实有仓或有挂单的、本地账本还记着未完事的 —— 一个不漏；
- **盘不清的**：盘了但对不上 —— 单独锁它自己一个币，下轮再盘，连续几轮不行就发邮件告警；
- **没东西可盘的**：配置里已删、交易所也没这仓、账本只剩流水痕迹（包括那个根本不存在的
  幽灵合约）—— **直接跳过**，不陪它耗时间，更不给它锁任何币的权力。

**五、“提前开了/提前平了”不是捣乱，但也不是“看到有仓就不管了”**

- 你要 5 张，已经手动开了 2 张 → 系统**补开 3 张**（不是“已有仓，跳过”）；
- 你开了 5 张 → 算出来差 0 张，自然不买；
- 你开了 8 张（超了）→ 系统**不砍你的仓**，等信号翻转时一起清；
- 你提前平了一部分 → 系统按**实际剩下的量**重算该卖多少，不会拿着平仓位前的旧量下大单；
- 刚手动平完系统就买回去？不会。有一阵“等你一下”的冷却（可调，含调成 0），冷却只锁
  这个币的买入，到点自动接着补差额。

**六、趋势仓(A) 和区间仓(B) 是两个口袋，各记各账、各倒各的**

关键事实：交易所那边只有一份净仓位，**不存在“这是 A 的”“那是 B 的”** —— 区分两个口袋
完全是本地账本在记账。所以“B 该止盈了，别把 A 一起平掉”靠三层保证：
各口袋各自记账 → 平仓量上限先把“另一个口袋已经挂的平仓量”扣掉 → 平仓单一律标成
“只减不增”。三层叠上去，B 平 0.3 张就是只动 0.3 张，A 那张不少。
反过来说，只有**信号真翻转**或**你按了强平**，才会两个口袋一起清 —— 那是本来就该清，不是误伤。

**七、钱的安全网拆了哪一道？一道没拆**

下单前先问交易所实际持多少（这道完全保留，只是不再“连坐”）、总仓位上限按最坏情况算
（从“一票归零”改成“按实际占用扣除”）、写不进库就不下单（完全保留）、
删账本必须人亲自确认（完全保留）。变的只有“谁该被锁”，不变的是“锁住时能不能保命”。

## 0. 现状诊断：僵化在哪里

代码事实（改造前需精确认识）：

| 阻断点 | 位置 | 现状 | 问题 |
|---|---|---|---|
| 账户级一票否决 | `run_real_trading_batch`：`_account_sync_ok = not failed_sync` | 并集中**任一**合约同步失败 → 全账户 `_entry_room()→0` | NAER 幽灵合约冻结 XRP/SOL/LTC/ETH 的病灶 |
| 他币风险拖累 | `_entry_room` 总仓位遍历：任一其它合约带 `sync_error/settlement_pending/external_open_orders` → `return 0.0` | 风险标记残留在**已废弃币种**的账本上，照样归零正常币种额度 | 与事故链第二环对应 |
| 失败原因不分层 | `synchronize()` 捕获异常后统一写 `s['sync_error']`，不区分"合约不存在(51001)"、"网络抖动"、"快照持续变化"、"存在未知订单" | 所有失败等权，全部升级为账户级阻断 | 真风险与被污染的非风险混为一谈 |
| 关闭路径被连带 | 对账失败轮的撤单/平仓逻辑与开仓共用同一 `_account_sync_ok` | 已移除币种每轮被撤单两次（`cancel_entries=True`）、白跑 20s+/币 | 变慢与变瘫同源于"对账范围没有事实判定" |

**事故修复 B（`_partition_sync_scope` 运行时豁免 + 三态 `instrument_exists`）已落地**，
它解决了"幽灵合约进入同步范围"的问题。本方案在其之上解决剩下的结构性问题：
**闸门语义仍是账户级布尔值，任何一次真实失败（哪怕是单个币种的瞬时抖动）依然会一票否决全账户**。

## 1. 设计总纲：三条不变式

1. **闸门只拦"新增风险"，永不拦"削减风险"** —— 对账结论最坏时，平仓、撤单、止盈止损兜底仍必须可执行；只有加仓/开新仓受对账状态约束。
2. **交易所是事实源，本地账本只是意图记录** —— "状态同步"（吸收人工开/平仓）由 `synchronize()` 的 `reconcile` 天然完成，不是靠闸门放行；闸门判断的依据应当是"该合约的事实是否已问清"，而不是"账本是否完美"。
3. **故障域最小化** —— 阻断范围与风险范围严格一致：某个币的事实没问清，只停这个币的开仓；只有"账户整体形状未知"才允许启动账户级阻断。

## 2. 新的对账范围判定逻辑：三分法

在 `_partition_sync_scope` 已有口径上，把每个合约显式判为三类之一（顺序即优先级）：

### SYNC（必须同步）—— 存在"待解释事实"

判定准则（任一命中即是）：

- 合约在**当前配置**内（无论账本是否干净——这是防重复开仓的第一道闸：配置说要 10 张、交易所已有 10 张人工仓，必须靠同步发现）；
- 出现在**交易所持仓目录或未成交挂单目录**中（真实敞口，铁律同步）；
- 账本记着真实敞口：`held>0`、非终态槽位、`unknown/cancel_requested/qfail`、兜底 algo 在位、`exchange_totals>0`、未终结市价平仓意图（沿用现有 `_ledger_open_interest`，含"终态残留不算敞口"修正）。

### ISOLATE（币种级隔离）—— 失败但可定界

同步**尝试了但失败**，且失败原因可归为"单合约局部问题"：

- 该币五步快照持续变化 / 存在未知订单 / 撤单未确认；
- 该币单笔查询瞬时失败（超时、限频 50011）。

处理：进入 `sync_failed_insts` 集合（见 §3），**只封锁该币加仓**；其账本风险标记只污染该币自己的额度，不外溢。

### SKIP（无事实可核对）—— 可忽略的账本残留

完全沿用修复 B 已有口径：账本干净 → 跳过；仅带风险标记 + 交易所**明确**无此合约（51001 三态为 False）→ 跳过并移出内存账本。三态中 **`None`（未知）永不归入 SKIP**。

### "真实风险"与"账本残留"的边界定义（本方案核心判据）

> 一个条目是否值得阻断，唯一取决于它背后**是否存在交易所侧可能真实发生的敞口或委托**。
>
> - 交易所目录里有它 / 配置里有它 / 账本记着未终结的它 → 真实风险，必须问清；
> - 交易所明确回复 51001 且账本只剩终态残留 → 账本残留，零阻断权；
> - 问不清（存在性未知、查询失败）→ 按真实风险保守处理，但**阻断范围仍是币种级而非账户级**。

## 3. 闸门触发条件优化：从布尔值到分级矩阵

### 3.1 状态模型改造（取代 `_account_sync_ok: bool`）

```
pos_mgr 新增：
  _account_entry_gate : bool      # 仅账户级事实保留（目录查询失败/持久化失败）
  _inst_sync_state: {inst: str}   # 每币同步结论：
                                  #   'ok'         —— 本轮事实已问清
                                  #   'unresolved' —— 本轮失败/未确认（隔离）
                                  #   'absent'     —— 无事实可核对（豁免，零权限）
trader 侧：
  sync_failed_insts: set          # 本轮 ISOLATE 名单（外循环产出，替代 failed_sync）
```

> 设计要点：不再把"本轮能否下单"与"账本健康度"挤在同一个布尔里；
> `_account_sync_ok` 语义**收窄**为账户级事件专用，币种级失败由 `_inst_sync_state` 表达。

### 3.2 闸门分级表

| 级别 | 触发条件 | 拦截范围 | 永不拦截的动作 |
|---|---|---|---|
| **G0 正常** | 币种同步通过，且快照信号一致 | 无 | — |
| **G1 币种隔离** | 单个合约 `synchronize` 失败（原因可定界到该币） | 仅该币**加仓/挂新开仓单** | 该币平仓、撤单、止盈止损、人工干预通道；**其它币种全部正常** |
| **G2 账户暂停开仓** | ① 持仓/挂单**目录查询失败**（shape unknown，现有逻辑保留）；② 总仓位上限 `max_total` 被未确认敞口击穿 | 全账户**新开仓** | 全账户平仓、撤单、reduce-only 操作 |
| **G3 全局停摆** | 仅 `not _storage_ok`（持久化不可用，下单意图无法落库=幂等保证失效） | 全账户一切下单（撤单仍可尽力而为） | 人工在交易所侧操作（无法也不应拦截） |

关键取舍：**G2 只由"账户形状未知"类事件触发**。单个币的五步快照失败、幽灵合约、
废弃币种 `sync_error` 残留——都不再有权关闭全账户。
这保住了资金安全网的最硬部分（不知道账户里到底有什么时不开新仓），拆掉的只是它的连坐部分。

### 3.3 `_entry_room` 的两处精准修改（口径描述，非代码）

1. **第一道闸改为按币判定**：
   `not self._account_sync_ok` → `not self._account_entry_gate or self._inst_sync_state.get(inst_id) != 'ok'`
   —— 每币下单前的对账屏障**强度不变**（该币自己必须先同步成功才准加仓），只是不再接受他币牵连。

2. **总额度遍历从"归零"改为"计占用"**：
   他币带风险标记时，不再 `return 0.0`，而是按**保守占用额**计入 `total`：
   - 该币账本记着的在途委托剩余量、`held`、交易所快照 `exchange_totals` —— 取 max 计入（现状本就如此）；
   - `unknown` 在途单按委托全额计入（最坏情形，安全且不让额度凭空消失）；
   - **纯残留标记**（`sync_error` 等）且交易所目录确认该币无仓无单 → 计入 0；
   - 该币连目录信息都不可信（存在性未知且同步失败）→ 其未确认敞口按账本记录值计入后，若 `total > max_total` 才归零正常币种额度。

   效果：总仓位安全网保留（未按最坏情形击穿上限就放行），但"一个废弃币的错误标记让全账户额度蒸发"不再发生。

### 3.4 失败重试与告警升级（利用既有邮件基础设施）

- **瞬时失败自然自愈**：G1 只维持一轮，下轮重跑五步快照，成功即恢复（现有 `_fill_generation`/快照循环已覆盖"持续变化"场景）；
- **连续失败升级**：按币维护重试计数，同一合约**连续 3 轮** ISOLATE → 发"持续对账分歧"告警邮件（并入项目既有的连续分析失败告警机制），邮件正文含：该币失败原因摘要、当前账本记录 vs 交易所最后一次可信快照、建议动作（`_cleanup_ghost_ledger.py --detail` 体检链接）；
- **7 天仍隔离中**：再发一次"建议人工清理/移出配置"提醒，但不自动删库（删除永远保留给人工决定，维持 `--scheduler-stopped` 硬约束）。

## 4. 幽灵合约 / 空账本处理：三道防线

| 防线 | 时机 | 动作 | 状态 |
|---|---|---|---|
| **事前** | 配置保存时（`app.py` 校验链） | 新增校验：`instId` 用 `instrument_spec` 三态查询，**明确不存在（False）→ 拒绝保存**并提示；未知（None，如离线）→ 放行但记 warning | 本方案新增 |

| **事后** | 轮初对账 | `_partition_sync_scope` 运行时豁免（修复 B，已落地）；`_cleanup_ghost_ledger.py` 人工彻底清库（已落地） | 已完成 |

补充一条自动隔离准则（在修复 B 之上的增量）：对配置**外**、交易所目录**外**、且
`_ledger_open_interest=False` 的条目，其 `sync_error` 等风险标记应随内存丢弃一并失效——
修复 B 已把条目移出 `_entry_room` 遍历，本方案进一步规定 trader 侧**不得再依据这类残留标记
触发任何级别的闸门**。

## 5. 状态感知：先算账再决定做多少（不是「有仓就不动」）

这是本方案语义上最重要的转变：**"跳过加仓/跳过平仓"是算出来的结果，不是规则，更不是闸门的豁免通道**。
检测到已有仓位只是第一步，第二步必须算"够不够"：

```
实际下单量 = max(0, 方向总额度 − 已占用)
方向总额度 = A(趋势仓)目标量 + B(区间仓)目标量
已占用     = max(交易所真实持仓, A账本 + B账本) + 各篮子在途开仓单剩余量
```

→ 不够就**补足差额**（目标 5、人工已开 2 ⇒ 补 3）；够了才算出 0 而跳过；超了不减不干预。
现状已部分具备，逐场景明确如下：

### 5.1 手动提前开仓 → 先算账，不够就补足

- 轮初同步时 `reconcile` 把交易所真实持仓吸收进账本（`【对账·absorb】`，已实现）；
- 更硬的一层：`_entry_room` 的占用取 **`max(交易所快照, 账本合计)`**，所以人工仓即使尚未被账本吸收，
  也一定计入占用 —— "人工提前开 + 系统再开一遍"这条路本来就关着；
- `room = target − real − pending` 天然给出补开量：目标 5、人工 2 ⇒ 补 3；目标 5、人工 5 ⇒ `room=0` 跳过；
- **维持既有"提前仓超量不干预"原则**：系统不平掉超出 `fixed_position` 的人工仓，只在信号翻转的平仓窗口统一清同方向全部持仓（项目既定规范，不改动）；
- 本方案新增的仅是：这一切**不再被他币的对账状态阻断**——XRP 同步成功、人工提前开了 2 张而目标 5 张，
  系统照常补开 3 张，同时 SOL/LTC/ETH 各自处理，互不牵连。

### 5.2 手动提前平仓 → 按真实持仓重算该平量

- 人工部分平仓 → `reconcile` 等比例摊减各篮子（`【对账·shrink】`）→ 平仓量按**摊减后**的篮子 `held` 重算，
  绝不按平仓前的旧量下大单；
- 人工全部平掉 → 交易所持仓归零、账本 held 归零 → 平仓路径因无仓可平自然跳过，且多余的平仓挂单被撤销
  （`_amend_slot_size` 的 `target<=0 → 撤单`、`_cancel_entries` + 快照循环已覆盖）；
- **补足要等人工冷却到期**：检测到外部平仓会触发 `hold_entries` → `pause_until`
  （配置项 `manual_close_pause_minutes`）。这是防"你刚手动平掉、系统下一轮立刻买回去"抢方向盘，
  不是永久跳过；冷却到期后仍按 §5 的减法补足差额。冷却只锁**该币开仓**，不锁平仓撤单、不牵连他币；
- **状态感知显式化（新增）**：币级同步发现持仓消失、且该方向存在我方未成交平仓挂单时，
  日志明确标注"检测到人工平仓事实，撤销冗余平仓单"，把隐式行为显式化，便于审计。

### 5.3 A/B 篮子隔离：各记各账、各平各仓（安全网不加码也不缩水）

先明确一个物理事实：**交易所侧只有一份净头寸，没有"A 的"和"B 的"之分**。
篮子隔离是本地账本的记账归属（`BUCKET_TREND`/`BUCKET_RANGE` 各自 `held/avg_px/slots`），
因此"B 止盈不许连坐 A 的仓"由三层保证，缺一层都不成立：

| 层 | 机制 | 效果 |
|---|---|---|
| ① 记账隔离 | 成交回报按 `bucket` 入账，各篮子独立 `held` | B 的平仓量只按 B 的 `held` 算 |
| ② 软件封顶 | `_exit_room` = 真实同向持仓 − **其它篮子已挂平仓量** | 两篮子不会重复平掉同一批仓 |
| ③ 交易所硬约束 | 平仓单一律 `reduce-only` | 物理上不可能把平仓单变成反向开仓 |

- 举例：A 持 0.5、B 持 0.3，B 触发止盈 ⇒ 只挂 0.3 张 reduce-only，A 的 0.5 张一张不少；
- 开仓侧两篮子**共享方向额度池**（`targets[dir] = A_size + B_size`），靠"本篮子之外全部在途开仓单计入占用"
  避免同向重复下单；本方案把额度污染改为"计占用"（§3.3）后，该共享池机制不变；
- 唯一"两篮子合并清算"的时点仍是长周期反转 / 夜间风控强平 / 人工强平 —— 策略本意，不是误伤；
- 闸门分级**最小到币种**，不设"篮子级连坐"：A 篮子出现账本分歧只锁 A 篮子的加仓，
  B 篮子的止盈挂单、减仓动作一律照常。

### 5.4 方向冲突保护（安全网不缩水）

人工在交易所开了**反向**仓（如策略看多、人工开空）：现有"仅净持仓全仓/逐仓方向支持"判定
（`supported = 净持仓模式`）与快照信号已能拦截——保留不变，判 G1 隔离该币并告警，**只停该币**。

### 5.5 手动按钮通道（`manual_direction` / 人工强平）

- 人工强平 → `pause_until` 冷却（已有）：冷却只封锁**该币**加仓，不冻结账户、不拖累他币——`_entry_room` 现状即币种级，保留；
- `manual_direction='long/short'` 方向锁语义不变（开仓窗口仍需真实共振），它属于信号层，不与闸门层交叉。

## 6. 定时任务 × 手动交易的优先级协调

明确一个统一的裁决模型，替代目前散落在各代码路径里的隐性优先级：

```
优先级从高到低：
  P0 人工强平 / 紧急停止        —— 无条件执行，可打断一切（现状保留）
  P1 交易所在途真实事实          —— 未确认的未知单、外部挂单：系统让路，
                                  撤销我方加仓单，绝不与其抢额度、抢对手价
  P2 人工挂单 / 人工持仓         —— 视为"环境的一部分"：计入额度占用、
                                  可被 reduce-only 单合法减掉，不强平超额人工仓
  P3 调度器计划动作              —— 只在 P0~P2 划定的剩余空间内执行增量操作
```

协调细则：

1. **幂等保证不依赖全局锁**：`cl_ord_id` 打标 + 下单意图先落库 + `unknown` 标记 + 反查
   `probe_order_by_cl_id`（均为现有机制）→ 即使闸门降为币级，单币"下单前必须同步通过"的
   屏障仍在，重复开仓路径依旧封闭。
2. **观察模式（`trade_enabled`）成为失败软着陆区**：51001 自动降级、连续对账失败告警后
   人工可一键转入观察——任务"不摆烂"的正确形态是**降级为只分析+邮件提醒**，而不是全账户停摆。
3. **配置变更即时消化**：`pause_until`、`fixed_position` 调整等人工干预由下轮读取配置自然
   生效（现状），配合既有的 excess-cancel 逻辑（撤多余加仓单/补不足），不因"改配置导致账实
   短暂不符"触发任何阻断——因为对账判定以交易所为准，配置只是目标。

## 7. 资金安全网保留清单（防回归红线）

以下既有保障**全部保留**，任何实现不得顺带拆除：

| 安全网 | 机制 | 本方案影响 |
|---|---|---|
| 防重复开仓 | 每币下单前 `synchronize` 屏障 + 快照循环 + `_entry_room` 额度核算；**占用取 `max(交易所, 账本)`** | 屏障从"账户级+币级"简化为"纯币级"，**强度不变**；max 占用口径不动，人工提前仓必被计入 |
| 不足额必补足 | `下单量 = max(0, 方向总额度 − 已占用)`，非"见仓即跳" | 保留并显式化（§5.1、P4 日志），不因闸门降级而漏补 |
| A/B 篮子隔离 | 记账按 `bucket` + `_exit_room` 软件封顶 + `reduce-only` | 保留；闸门不下沉到篮子级连坐，不因 A 锁 B（§5.3） |
| 防漏平仓 | 信号翻转强平、夜间风控、止损止盈、兜底 algo 委托 | G1/G2 均不拦平仓，**覆盖反而更全**（以前被幽灵合约拖死时平仓也可能延误） |
| 未知单保守处理 | `unknown/cancel_requested` → 该币禁补单、额度按最坏占用 | 保留，范围限定在当事币种 |
| 总仓位上限 | `max_total` 全局额度遍历 | 保留，"归零"改"计占用"，击穿判定按最坏情形 |
| 持久化 fail-stop | `_storage_ok=False` → G3 全局停单 | 保留（乐观锁 latch 场景下这是唯一正确行为） |
| 账本删除人工确认 | `--scheduler-stopped` 硬约束 | 保留，自动化只做"内存豁免+告警"，**永不自动删库** |

## 10. 落地实录与设计差异（2026-09-28 实现完成）

代码已按 P1~P4 全部改完，`crypto/task/_smoke_soft_gate.py`（22 场景）+ 全套 18 个 task 层冒烟均绿。
实现过程中相对设计稿有四处**必要偏移**，记录在此以免后来人按稿索骥：

1. **`_inst_sync_state` 多一个第四态 `'syncing'`**。设计稿只写了 `ok/unresolved/absent` 三态，
   但 `synchronize()` 内部做 excess 检查时会以 `refresh=False` 回调 `_entry_room`；若此路径
   严格要求 `== 'ok'`，则「本轮正在对账的正常币」会被自己锁住，表现为每轮误撤所有开仓单。
   故进入 `synchronize()` 先置 `'syncing'`，成功置 `'ok'`，异常置 `'unresolved'`。
2. **P3 的事前防线未新增代码**：配置保存校验 instId 存在性（51001 拒绝保存）在
   `app.py::_validate_instruments_exist` 已存在，本轮只补了「运行中 51001 → 自动降级观察」与
   「连续 N 轮隔离 → 告警」两条。自动降级**只写内存 `_auto_watch`，不改用户配置文件**
   （自动改配置 = 替人工做主，且难回溯）。
3. **`_account_sync_ok` 字段名保留**，只把语义收窄，另设 `_account_entry_gate` 属性做可读别名
   （存量调用方与冒烟桩直接赋值该字段，改名会波及一片且无功能收益）。
4. **trader 侧轮初逐币对账循环抽成 `_sync_round_instruments()`** —— 纯为可测性做的重构，
   行为与原内联代码一致；否则这些判定只能靠跑真调度轮验证。

冒烟脚本未覆盖、必须上线后看日志人工确认的两项：

- **P3 事前防线**（配置保存时 51001 拒收）只在 `app.py` 路径上，_smoke_soft_gate 不导入 `crypto.app`，
  需真实保存一次错配 instId 的配置看是否被拦；
- **P4 三段式日志的实际排版**（脚本只断言 `_last_room_detail` 内容与关键字），真实可读性要在
  实盘 `trade_*.log` 里看一行完整挂单记录。

## 一句话总结

把闸门从"任一账目对不上 → 全账户归零"改造成"**事实问不清谁、就只锁谁；账户形状问不清、才锁账户；平仓与撤单永远放行**"——
幽灵合约与账本残留被三段判据（SYNC / ISOLATE / SKIP）精确隔离在权限体系之外，
而每币下单前的对账屏障、总仓位最坏情形占用核算、持久化 fail-stop 这几道真正的资金安全网一道不缩。

同时明确一句与闸门无关但同等重要的口径：**下单量是减法算出来的（目标 − 占用），
不是"看到有仓就跳过"**；不够就补、够就算了、超了就不动，A/B 各记各账、各平各仓。
