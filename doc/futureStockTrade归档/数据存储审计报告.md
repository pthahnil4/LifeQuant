## 一、审计结论速览

| 类别 | 文件数 | 总占用 | 建议迁移 |
|---|---|---|---|
| 临时缓存（`__pycache__`/日志/截图/测试DB） | 60+ | ~2.5 MB | ❌ 全部不迁移，可安全清理 |
| 本地持久化（SQLite + CSV） | 9 | ~1.2 MB | ⚠️ 部分迁移（详见下表） |
| 待迁移 JSON/配置 | 2 | <1 KB | ✅ 强烈建议迁移 |

**关键发现：**
1. `data/training.db` 主库 5 张表**全部为空**（0 行），WAL 文件 218 KB 但主库仅 4 KB——说明库已初始化但尚未承载真实业务数据，是迁移的最佳窗口期。
2. `data/_test_training.db` 含少量单元测试数据（2 users / 1 session / 1 match / 2 results），**非生产数据**，不应迁移。
3. `futures/future.csv`（67 行 × 33 列）是期货模块的**核心主数据**，被 6 个模块读取，迁移价值最高。
4. `futures/star品种行情.csv` 是 `futures_config.json` 中 `starred` 列表的**派生快照**，迁移 JSON 后此 CSV 可降级为视图或按需重建。
5. `lc_indicators.csv` / `trend_atr_all_result.csv` / `screenshot_*.png` 等均为**一次性调试产物**，不应进入数据库。
6. `config.py` 中已预置 TDengine 连接（`TDENGINE_REST_URL=http://49.235.31.162:16041`），但 `TDENGINE_CACHE_ENABLED` 默认关闭——迁移时可按需启用作为时序快照存储。

## 三、迁移可行性评估

### 3.1 收益
1. **统一数据源**：消除 CSV/JSON 双轨制，`futures_adapter.py`/`stock_adapter.py`/`star_market.py` 的读取逻辑收敛到 DAO 层。
2. **多用户支持**：`symbol_watchlists.user_id` 字段天然支持按用户隔离自选/星标，当前 JSON 是全局共享。
3. **时序可追溯**：`market_snapshots` 按 `snapshot_at` 版本化后，可回放任意历史时点的趋势/指标状态。
4. **回测可对比**：`backtest_runs` 集中存储后，前端可做跨策略/跨品种/跨时段对比分析。
5. **与 TDengine 协同**：高频快照（如 1m/15m）可下沉到已预置的 TDengine，SQLite 仅保留聚合/元数据。

### 3.2 风险与对策
| 风险 | 对策 |
|---|---|
| `future.csv` 被 8 处硬编码读取 | 提供 `futures_dao.py` 兼容层，保留 `get_futures_categories()`/`get_futures_code_name_map()` 等既有 API 签名，内部改读 DB |
| `star品种行情.csv` 拖拽排序逻辑依赖 CSV 行序 | `symbol_watchlists.position` 字段承接排序，`star_market.py` 的 `_sync_starred_to_csv()` 改为 `_sync_starred_to_db()` |
| GBK 编码的 `trend_atr_all_result.csv` | 迁移前统一转 UTF-8，或作为一次性产物不迁移 |
| `training.db` 当前为空，迁移窗口期短 | **立即执行**：在真实业务数据写入前完成 schema 扩展，避免后续数据迁移成本 |
| WAL 文件 218 KB 未 checkpoint | 迁移前执行 `PRAGMA wal_checkpoint(TRUNCATE)` 合并到主库，确保数据一致性 |

### 3.3 建议迁移顺序
1. **Phase 1**（低风险）：`futures_config.json` + `stock_config.json` → `symbol_watchlists` 表
2. **Phase 2**（中风险）：`future.csv` 静态列 → `futures_symbols` 表；保留 CSV 作为只读兼容源
3. **Phase 3**（中风险）：`future.csv` 动态列 + `star品种行情.csv` → `market_snapshots` 表
4. **Phase 4**（可选）：`dual_timeframe_backtest_results_*.csv` + `strategy_comparison_*.csv` → `backtest_runs` / `backtest_trades`
5. **Phase 5**（清理）：删除 `_test_training.db`、日志、截图、`lc_indicators.csv` 等临时产物
